# 职业比赛教育版 V1

> 当前开发顺序与未通过项统一查看 [当前状态](education-status.md) 和 [范围约定](education-scope.md)。本文保留历史实现与验收证据，不代表所有能力已完成交付。

教育版与通用版共享仓库；开发分支为 `codex/education-v1`，基于 `4e7c922c`。没有合并旧 `competition-specific` 分支。默认 `APP_EDITION=general`，已有通用项目不转换。

## 本地启动

```bash
# 在教育版 worktree 内，先安装项目原有 Python/Node 依赖
uv sync
npm ci --prefix frontend
npm ci --prefix editor-pptist
node scripts/build_pptist_editor.mjs
.venv/bin/python scripts/education_dev.py init
.venv/bin/python scripts/education_dev.py backend
# 另开终端
.venv/bin/python scripts/education_dev.py frontend
```

访问 `http://127.0.0.1:3190/education`，后端仅监听 `127.0.0.1:5191`。注册教育版独立账号。`EDUCATION_BACKEND_PORT` / `EDUCATION_FRONTEND_PORT` 可改变端口。启动器不读取通用版 `.env`；可在 `.education-runtime/providers.env` 配置模型及解析提供商，或使用现有管理员配置机制设置教育版账号。

数据库、上传目录、随机站点密钥均置于被忽略的 `.education-runtime/`。教育版使用 `banana_education_auth_token` / `banana_education_csrf_token`，通用版 cookie 名不变。账号及积分数据不自动复制。容器构建通过 `.dockerignore` 排除本机密钥、数据库、上传、验收文件及依赖缓存。不要把密钥放入源码、验收文档或版本库。

## 独立部署

将 `.env.education.example` 复制为未跟踪的 `.env.education`，填写独立随机 `SECRET_KEY`、真实 HTTPS 域名、模型/解析配置和管理员凭据。执行：

```bash
docker compose -f compose.education.yaml up -d --build
```

Compose 项目名为 `banana-education`，数据库与上传各用独立命名卷；前端只绑定宿主机 `127.0.0.1:3190`，由站点网关提供 HTTPS。沿用主仓库的容器构建文件，前端包含 PPTist 构建产物。`docker compose config --quiet` 已通过；此配置未在生产环境部署。不要把通用版的数据卷挂给教育服务。

迁移 `032_competition_education` 仅新增教育内容、内容版本和请求去重表。升级前按现有部署规范备份数据库和上传目录；回退 032 会移除教育业务表，因此保留教育数据时应回退应用版本而非删除业务表。

## 数据与工作流

- `CompetitionDocument` 是唯一可修改的内容源；页面 ID 为 UUID。大纲、逐页描述、素材待补清单均从同源记录导出。内容版本保留完整快照。
- 页面包含上屏文字、版式、素材需求、独立讲稿/动作提示、章节与岗位引用。素材绑定指向页面/岗位 ID；重排时重新计算清单页码。删除页面后孤立的证据事项明确标注待重新关联。
- 导入稿保留原始 Markdown，未修改页面时逐字导出；不要求先转换成默认结构。手工修改/AI 改写之后对应记录成为新版本。
- 模型负责理解、集中补问与逐页编写。每批 5 页，校验页面 ID、顺序、类型和结构后才整批发布；失败不发布半套内容。使用现有账号级 Provider 快照。
- 本仓库 `backend/services/competition/resources/` 固化 skill 版本 `world-skills-2026-09-21.v1`、页面骨架与事实边界。默认五章四岗 47 页是产品预设，不是官方赛制要求。支持 1–12 岗与不超过 100 页；极小目标页数仍需保留必要章节，差异会提示。
- 年份与规则来源属于项目数据，未确认时留空。不套用历史分数；缺图占位，不生成虚构成员或证书。
- 内容保存使用版本比较；旧任务完成时不能覆盖较新内容。浏览器的未保存草稿保留自己的版本号，后台刷新不会使旧草稿取得新版本的写入权限。
- 试稿默认封面、团队页、首个核心技能内容页；可换选，至多三页。图片使用现有 `page_ids` 接口能力，剩余生成只提交没有有效图片的页。价格来自现有积分估算，不复制竞品钻石定价。
- 图片生成期间禁止改变其来源。文字/版式/风格/模板/绑定素材或页序变化使受影响图片失效；已成功且输入未变的页面复用。失败页可再次提交，按原有计费结算成功页。
- 请求去重以项目内 `request_key` + 请求摘要为依据，重复提交复用任务；浏览器保留网络失败时的请求标识。
- 图片成稿后进入原有语义转换与 PPTist。新图片会标记旧编辑稿过期；显式重新转换产生新编辑版本，保留旧版本。编辑器内“导出当前版本”导出手工修改后的文件。工作台“初始可编辑 PPTX”对应最近转换产物，PDF 对应生成图片，不代表后续手工编辑稿。

## API

所有教育业务接口要求 `APP_EDITION=education` 并沿用项目归属与认证检查。

| 路径 | 行为 |
|---|---|
| `GET/POST /api/competition/projects` | 账号内项目历史 / 新建 |
| `GET/PATCH /api/projects/:id/competition` | 快照 / 带 revision 保存 |
| `POST .../import` | 大纲与逐页描述原文导入 |
| `POST .../messages` | 项目字段或选中页局部改写 |
| `POST .../plan` | 理解、页面规划、内容编写与校验任务 |
| `POST .../images` | 试稿、剩余页、失败页生成 |
| `POST/DELETE .../template` | 上传/清除独立参考模板 |
| `GET .../exports/:kind` | outline / descriptions / checklist Markdown |
| `GET .../revisions`, `POST .../restore` | 历史快照与恢复新版本 |

长任务沿用 `Task`、任务管理器与积分预留/结算。文档快照含当前任务、生成进度、真实积分估算、缺失页面列表。图片部分失败时保留成功页，工作台显示失败数量并支持单页重试；失败解析文件可移除引用后继续策划。浏览器刷新可继续查看后台任务；服务进程崩溃仍沿用现有离线 `recover-interrupted-tasks` 命令，必须先停 worker 和核验备份，失败任务释放预留后由用户重新提交，不自动重放付费任务。

## 验收边界

通用版仍使用原主页、认证和生成入口。教育内容不能通过通用页面修改接口绕过同源记录；共享底座未包含学校组织、多赛事、评分报告或完整网盘。在线编辑沿用现有经过校验的文字、形状、表格、图片及分组能力；版式操作超出语义合同会拒绝保存，不声称完整 PowerPoint 功能覆盖。

### 真实验收补记

- 草莓脱敏材料：真实模型完成 47 页，大纲与逐页描述标题逐页对齐；规则脚本验证通过，章节过渡页为 4、10、15、39、46。缺失实测结果、采样周期 2 秒/5 秒冲突、照片缺失均进入待补清单。
- 餐饮服务：真实模型完成 18 页（目标 13 页为软约束，界面提示保留完整结构所产生的差异）。内容保持餐饮服务四岗，没有把 AI、机器人或软件系统写成项目能力。真实对话将展示时长改为 20 分钟，数据库核对确认 18 页内容、岗位和赛道未变；浏览器设置同步显示新时长。
- 三页试稿：封面、团队与核心技能页成功。首次图片检查发现补绘界面缺少示意标记，因此加入教育专用视觉证据要求后重新试稿：未知读数用空值，补绘界面标明“设计示意 · 非实测/实拍”，团队保留待补照片。此要求用于提示模型，不能替代老师对每张图片的事实核对。
- 浏览器提交剩余 44 页任务，只生成缺失页，试稿三页被复用。积分不足返回 402 且不创建付费任务；验收期间只给独立 `education-qa` 账号增加具备账本记录的本地测试积分，不涉及实际充值。
- 人工语义样例（3 页，不代表模型识别）：在线改字、保存、刷新重开成功；导出当前版本含原生文字、卡片、分组、图片与表格。已实际在 WPS 打开并改写标题后撤销，中文无明显溢出；LibreOffice 渲染的 3 页 PDF 已逐页查看。WPS 提示本机缺 Noto Sans CJK SC，但替代字体可正常显示；生产镜像含该字体，接收端字体仍影响排版。
- 文件上传实测：浏览器选择 TXT 材料后完成上传、项目绑定与自动解析，数据库原文与上传文件一致。修复了浏览器清空 file input 导致异步 FileList 丢失的问题，并加入回归用例。
- 补充针对性验证：教育后端 28 项通过；前端教育用例 4 项通过；最后一次 TypeScript 与 Vite 构建通过。

### 人物参考图交互补齐（2026-09-26）

团队介绍页在大纲、逐页描述、素材视图中直接展示成员照片卡片，与竞品截图的成员槽位流程对齐：单人照上传/更换、缩略图、成员姓名与岗位编辑、拖拽绑定/交换、增加/删除槽位。图片绑定页面 ID 与岗位 ID，替换同一槽位不会叠加旧照片；后台拒绝重复槽位。导入稿普通开场内容不再自动视作团队页，用户可明确指定团队介绍页；改标题保留标记。更换照片仅使相关团队页图片失效。

浏览器在隔离的离线验收项目使用明确标注 QA 的中性图片验证上传、姓名岗位编辑、保存与刷新恢复。真实草莓项目没有用户成员照片，保留空槽位；尚未验证真实人像生成的身份保真度。组件测试覆盖上传/替换/拖拽交换/成员编辑，后端覆盖页面隔离、重复绑定与其他成稿保留。页码列表和内容区独立滚动，避免选择页面后显示空白区域。
