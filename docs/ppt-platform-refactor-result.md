# 世职赛 PPT 平台重构完成报告

> 完成日期：2026-07-30
> 产品定位：面向职业教育竞赛场景的智能 PPT 策划、生成、编辑与交付平台
> 实现原则：复用现有大模型、PPT 生成、生图、图片处理、在线编辑和导出能力，在其上增加赛事配置、项目上下文、模板资产和数字员工编排层。

## 1. 当前赛事支持矩阵

| 赛事 | 支持等级 | 当前行为 | 专属数据边界 |
|---|---|---|---|
| 世界职业院校技能大赛 | `FULL` | 可进入完整生成流程，启用 39 页结构、五项评分、专属提示词、模板和讲解稿上下文 | 唯一具备专属规则、评分、案例标识和模板的赛事 |
| 挑战杯 | `GENERIC` | 可创建项目并使用通用生成、视觉模板、素材、编辑和导出能力 | 不显示专属评分、案例或专业模板 |
| 中国国际大学生创新大赛 | `GENERIC` | 同上 | 不显示专属评分、案例或专业模板 |
| 全国大学生职业规划大赛 | `COMING_SOON` | 可在选择器查看，阻止进入正式生成流程 | 显示“正在建设专属能力” |
| 职业院校技能大赛教学能力比赛 | `COMING_SOON` | 同上 | 不构造尚未配置的业务数据 |
| 自定义赛事 | `GENERIC` | 使用通用 PPT 流程 | 不启用赛事专属规则、评分或案例 |

赛事列表、启用状态和支持等级由统一 `CompetitionConfig` 提供；前端带本地安全配置，运行时优先读取 `/api/platform/competitions`。

## 2. 世界职业院校技能大赛专属能力

- `wvcc` 为唯一 `FULL` 赛事，推荐页数为 39 页。
- 比赛类型配置争夺赛、排位赛和自定义；赛道、主题均由配置提供，不散落在页面判断中。
- 五项评分维度为技能水平、职业素养、应用价值、团队合作、创新创意。
- 内置 39 页系统大纲模板，结构源于用户提供的 PPT 与逐字稿模板，而不是 UI 示例中的 38 页占位数据。
- 大纲提示词、页面计划、内容生成、图片视觉上下文和讲解稿生成均可获得赛事与评分上下文。
- 评分检查员只在 `wvcc` 下可用，通用赛事不会生成伪造评分结论。

## 3. 其他赛事的受控支持方式

- `GENERIC`：保留主题输入、资料上传、通用大纲、视觉模板、生图、图片处理、在线编辑和导出。
- `COMING_SOON`：选择后禁用类型、赛道、主题及创建按钮，并明确提示建设状态。
- 通用工作流不包含评分检查步骤；非 `wvcc` 模板禁止携带已配置的评分维度。
- 新赛事只通过配置切换支持等级，无需在各页面增加赛事名称判断。

## 4. 新增的大纲模板能力

新增独立的“大纲模板中心”，与视觉模板库分离，提供：

- 新建、编辑、复制、删除、归档、搜索和筛选；
- 系统、团队、我的三种范围以及草稿、发布、归档三种状态；
- 赛事、比赛类型、赛道、主题和通用范围绑定；
- 章节、用途、推荐页数、评分维度、推荐讲解人、素材要求和生成指令；
- JSON 导入、导出、预览、应用到项目；
- 将当前项目大纲保存为私有草稿模板；
- 每次编辑自动增加版本并保存历史快照；
- 按“赛事 + 类型 + 赛道 + 主题”至平台通用模板的五级优先级匹配。

模板通过 `OutlineTemplate` 数据表和 `/api/outline-templates` 持久化；后端不可用时，用户模板仍可在本地仓库工作。

## 5. 新增的素材管理能力

素材中心按当前项目读取真实素材，支持上传、删除、AI 生成与图片处理，并复用现有素材管理弹窗。生成、整图编辑、框选编辑和擦除结果可回到项目素材库。

生图上下文包含赛事、赛道、主题、章节、当前页面目的、视觉风格、图片用途和世职赛评分语境，避免生成脱离项目的通用科技图。在线编辑继续保留 AI 生图、替换图片、抠图/透明背景、纯白背景、背景更换、扩图、清晰度增强、裁剪、框选编辑和图片版本能力。

## 6. 新增的数字员工

| 数字员工 | 主要职责 |
|---|---|
| 竞赛总策划 | 判断支持等级、读取项目、编排生产流程 |
| 大纲架构师 | 匹配模板、生成/修改大纲、规划页面 |
| 内容分析师 | 解析材料、提炼证据、识别缺失 |
| PPT 视觉设计师 | 读取视觉模板、统一风格、页面重设计 |
| 素材生成师 | 生图、抠图、背景处理、项目素材入库 |
| 评分检查员 | 检查世职赛五项评分覆盖和整改点 |
| 演讲稿助手 | 生成逐页讲稿并绑定页面 |
| 交付工程师 | 页面完整性预检和多格式交付 |

所有角色由 `DigitalEmployee` 配置驱动，可限定赛事、调用方式、能力和服务映射。

## 7. 数字员工与现有服务的映射关系

| 数字员工 | 复用的真实服务 |
|---|---|
| 竞赛总策划 | 项目读取、`/api/projects/understand` |
| 大纲架构师 | `generate/outline`、`refine/outline` |
| 内容分析师 | 参考文件列表/解析、项目理解 |
| PPT 视觉设计师 | 用户视觉模板、页面图片编辑 |
| 素材生成师 | `materials/generate`、`materials/process`、素材上传 |
| 评分检查员 | 真实项目页读取、世职赛评分配置、outline/description refine |
| 演讲稿助手 | 单页和全项目 narration 生成 |
| 交付工程师 | 项目/导出记录检查、PPTX、可编辑 PPTX、PDF 等导出 |

`FULL` 工作流固定为 8 步，`GENERIC` 固定为 6 步；`COMING_SOON` 无可执行工作流。任务具有 `PENDING / RUNNING / SUCCESS / FAILED / CANCELLED` 状态，支持取消和失败重试，不存在自动无限循环。

## 8. 新增或修改的页面

- PPT 工作台：赛事选择、支持状态、类型/赛道/主题、模板、页数、版本和完成度。
- AI 生成：嵌入统一平台外壳，继承赛事和项目上下文。
- 大纲规划：显示赛事、模板、页数与评分语境，可将当前大纲保存为模板。
- 大纲模板中心：完整的业务模板资产管理。
- 模板库：按赛事、赛道、主题做受控视觉模板匹配。
- 在线编辑：进入真实页面预览与编辑链路，不是说明页或静态占位。
- 素材中心：项目素材和 AI 图片工具统一入口。
- 导出中心：真实导出接口、交付预检和历史导出记录。
- 全局数字员工总控台：在平台外壳及旧核心编辑页均可召唤。

UI 使用真实 React 组件和 HTML 结构，未将参考图作为背景。详细映射见 `docs/ui-reference-map.md`。

| 路由 | 页面 |

## 11. 修改或新增的 API

新增：

- `GET /api/platform/competitions`
- `GET /api/outline-templates`
- `POST /api/outline-templates`
- `PUT /api/outline-templates/:id`
- `DELETE /api/outline-templates/:id`

## 12. 复用的底层能力

本次没有重复实现模型或导出引擎，继续使用已有的项目材料解析、大模型生成、流式大纲、页面描述、页面生图、图片编辑、图像版本、素材上传/处理、讲解稿、PPTX、可编辑 PPTX、PDF、图片包和视频导出能力。

## 13. 当前可运行的完整业务流程

1. 在工作台选择赛事并读取支持等级。
2. 选择比赛类型、赛道、主题、目标页数和视觉风格。
3. 创建或选择项目，上传逐字稿及项目资料。
4. 匹配大纲模板，或由 AI 生成并编辑大纲。
5. 生成页面描述和页面图片。
6. 在在线编辑中修改图片、处理素材、维护讲解稿和页面版本。
7. 通过数字员工总控台查看分步任务、结果，必要时取消或重试。
8. 在导出中心预检并导出 PPTX、可编辑 PPTX、PDF、图片或讲解视频。

项目、赛事上下文、大纲模板、视觉模板、页面、素材和讲解稿始终由同一个 `projectId` 串联。

## 14. 当前未完成或受限的能力

- `TEAM` 权限范围、当前用户所有权和系统模板只读规则已建模并实施基础约束，但尚未接入组织、团队成员和角色级 RBAC 管理后台。
- 模板版本历史可查看且编辑会生成快照；当前没有“一键回滚到历史版本”的独立 API。
- 数字员工是前端确定性服务编排层，任务状态在当前会话内可观察；尚未建设跨进程、可恢复的独立工作流队列。
- 评分检查当前提供结构和内容覆盖检查，不等同于官方评委打分或合规认证。
- 构建仍提示主包超过 500 kB 及一个动态/静态混合导入警告，不影响构建和运行，后续可做路由级拆包。
- 其他赛事没有专属规则、案例、提示词或专业模板；这是当前产品边界，不是以伪数据填补的缺口。

## 15. 后续扩展其他赛事的方法

1. 在前后端赛事目录增加 `CompetitionConfig`，初始设为 `GENERIC` 或 `COMING_SOON`。
2. 仅在取得可信规则和案例后，配置评分维度、提示词 profile、页面数和专属模板。
3. 增加赛事专属大纲模板并绑定赛事、类型、赛道和主题。
4. 为专属评分检查和讲解稿增加经过验证的服务/profile。
5. 增加对应测试，确认通用赛事不会意外获得其他赛事的数据。
6. 验证完整生成与导出链路后，才将支持等级切换为 `FULL`。
