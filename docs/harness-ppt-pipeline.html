1. 系统总览

兰台（Banana Slides）把 PPT 生产拆成可校验的多段链路：理解材料 → 组织叙事 → 逐页描述 → 结构计划 → 成图 → 导出。Harness 模式在文本阶段就开始注入「页面角色、关系类型、真实约束」，并在成图前生成可持久化的结构计划，避免只靠一次性 prompt 碰运气。

用户输入（主题 / 大纲 / 材料 / 旧稿） │ ▼ 创建项目 Project │ ├─ generation_mode = fast ──► 常规 AI 大纲/描述 ──► 成图（需模板或风格） │ └─ generation_mode = harness ──► 场景包增强文本 ──► 结构计划 Deck + PageVisualPlan │ ▼ 成图（可用场景包默认视觉） │ ▼ 预览 / 编辑 / 导出 PPTX·PDF

整条链路的「内容真相」始终来自用户材料与 AI 在大纲/描述阶段的输出；Harness 质检层负责检查是否够具体、是否可迁移到别的话题、数字是否可溯源、整套是否同质化，而不是替用户编造内容。

2. 用户入口与创建方式

首页（Home）提供多种创建路径，对应不同的起点材料：

入口用户给什么系统先做什么用户接下来去哪
Harness Agent 主题、受众、页数、场景包 一次性生成整套 Deck 计划（大纲+描述+视觉计划） 留在 Agent 面板编辑 → 风格预览 → 批量成图
混乱材料 / No-Think 一段杂乱想法或材料 自动整理成大纲 + 逐页描述 详情页 → 成图
大纲模式 结构化大纲（可附带描述） 生成或确认大纲；可选再生成描述 大纲编辑器 或 详情页
借鉴生成 参考 PPT + 自己的内容 分析参考稿结构，按你的内容重写 详情页（蓝图优先成图）
旧稿翻新 上传 PDF/PPTX 解析旧稿每页 → 提取标题要点与描述 详情页（默认 Fast，可再选手动 Harness）
Agent 入口始终使用 Harness 模式；其他入口可在首页选择 Fast 或 Harness，并挑选场景包（纸片人 / 课程讲义 / 产品发布 / 咨询汇报）。

3. Fast 模式 vs Harness 模式

Fast 快速模式 尽快进入大纲、描述、成图。无场景包结构计划。成图前通常需要模板图、风格文字或外部 Skill 之一。
Harness 高质量模式 文本阶段注入场景包叙事规则；描述完成后自动生成 Deck 结构计划与逐页视觉计划；成图时可使用场景包默认视觉。

Harness 的两层解耦（重要）

  • 结构层：页面角色、关系类型、构图模式、标签、数据契约、Swap Test — 对任何视觉来源都必须生效（模板图、用户风格、外部 Skill 也不能绕开）。
  • 视觉层：色板、材质、画风 — 仅在用户未指定视觉来源时，使用场景包默认视觉；用户模板/风格优先。

4. Harness 场景包

每个场景包 = 一种叙事结构 + 一套默认视觉。四包共用同一套 Harness 质检层。

场景包叙事侧重默认视觉气质
纸片人 Paper Operators 隐喻执行者：先定关系，再选无脸折纸小人执行核心动作 暖白纸模舞台、路径蓝、高空俯视
课程讲义 Lecture Deck 教学闭环：目标 → 概念 → 例题 → 小结 讲义板书风、靛蓝主色、可较高信息密度
产品发布 Product Launch 发布会叙事：悬念 → 揭幕 → 特性 → 参数 → 价格 → 行动 深色舞台、产品摄影级主视觉
咨询汇报 Consulting Report 金字塔原理：标题即结论句，图表主导，数据可追溯 深蓝灰 + 橙色 takeaway 强调

5. Harness 质检层（全场景包共用）

借鉴 paper-operators v2 思路，质检不只为纸片人服务，而是所有 Harness 项目的统一底座。

Phase 1 — 页级精度

  • 资产路由（5 种角色）：内容论证页、故事/案例卡、数据叙事页、封面/章节/收束页、参考型科普页。先定「这页在 Deck 里干什么」，再定怎么画。
  • 关系类型（12 种）：连接、交接、依赖、因果、反馈、对比、权衡、层级、转化、边界、分流/汇聚、张力。关系优先于装饰元素。
  • 构图模式：单节拍、单页多节拍、对照构图、极简封面/收束。
  • 纸片人专属：21 种执行者库 + 关系→执行者映射（关系优先，而非关键词碰运气）。
  • Swap Test（换文测试）：若这页换到同题材另一篇文章仍成立 → 警告「不够具体」；连续多页 asset/relationship/composition 完全相同 → 警告「模板锁定」。

Phase 2 — Deck 级连续性

  • truth_constraints：标题、要点里出现的数字与专名，写入「不可编造」清单，随成图 prompt 下发。
  • data_contract：数据叙事页额外约定 exact_values、禁止编造坐标轴/类别；咨询汇报与含数页面自动启用。
  • throughline（母题）：全稿共享一条视觉母题（如路径蓝丝带、橙色 takeaway、中央产品聚光）。
  • variation_axes（变化轴）：相邻页至少在 camera / 焦点 / 道具 / 强调色 等轴上分化，避免整套一个模板。
  • Deck 级 QA：汇总每页 Swap Test + 检查全稿是否过半页面同质化。
Swap Test 与 Deck 连续性检查当前为软警告：记录 QA issue，不阻断生成；便于后续在 UI 展示或人工复审。

6. 文本阶段：大纲与描述

Harness 项目创建 │ ├─► 大纲阶段 │ · AI 收到 Harness 核心指令 + 场景包大纲规则 │ · 要求：每页 reader takeaway、可命名 asset role、含数页禁止编造 │ · 产出：每页 outline（标题 + 要点） │ · 项目状态 → OUTLINE_GENERATED │ └─► 描述阶段 · AI 收到 Harness 核心指令 + 场景包描述规则 · 要求：source anchor、layout_intent、visual_focus、truth_constraints · 产出：每页 description（正文 + 可选 main_message 等） · 项目状态 → DESCRIPTIONS_GENERATED · Harness 副作用 → 触发结构计划生成（见下一节）

用户在 OutlineEditor / DetailEditor 中可随时修改大纲与描述；重新生成描述时会清除旧的 Harness 计划并重建，保证计划与最新文本一致。

7. 结构计划阶段

Harness 模式在描述就绪后（或 Agent 计划创建时）生成一组持久化结构产物：

DeckVersion（整套 Deck 计划 + QA 结果） │ ├── DeckVisualSystem（全稿视觉系统：色板、禁忌、一致性规则、母题） │ └── 每一页 ├── SlideVersion（该页 slide 计划快照） └── PageVisualPlan（该页结构+视觉指令） · page_role / asset_role · relationship_type / composition_mode · source_anchor / reader_takeaway · truth_constraints / data_contract（如有） · throughline / variation_axes / series_position · structure_prompt + style_prompt + visual_prompt · 单页 QA（含 Swap Test）

常规 Harness vs Agent 的差异

常规 Harness（Home 创建）Agent 模式
计划来源 从已有 Page 大纲/描述反推合成 DeckPlan LLM 一次性生成完整 DeckPlan，再落库
用户编辑 在大纲/详情编辑器改文本 → 重建计划 在 Agent 面板改 slide 内容与 visual plan → 可锁定单页
成图门槛 描述完成后直接可成图 需先「风格预览」2 页，再批量剩余页
项目状态 OUTLINE / DESCRIPTIONS / GENERATING / COMPLETED AGENT_PLAN_PENDING → STYLE_PREVIEW → GENERATING → COMPLETED

8. 成图阶段

成图前系统组装「视觉指导」：决定听谁的画风，以及必须遵守的结构与质量底线。

视觉优先级（从高到低）

  1. 外部风格 Skill（若启用）
  2. PPT 蓝图页（借鉴生成场景）
  3. 用户上传的模板图
  4. 用户填写的 template_style 文字
  5. Harness 场景包默认视觉（无用户视觉时）
  6. 仅由本页描述决定风格

Harness 成图时永远注入

  • 当前页 PageVisualPlan 的结构指令（与视觉来源无关）
  • 场景包默认视觉指令（仅当视觉未被模板/蓝图/外部 Skill 覆盖）
  • 4K 成图质量硬约束（文字可读、无畸形、无伪影等）
  • truth_constraints / data_contract（含数页）
  • 产品发布包的素材状态（真实产品图 vs 概念占位）
DetailEditor / SlidePreview 触发成图 │ ├─ 读取 Page 描述 + 模板/蓝图/Skill ├─ 查找 PageVisualPlan ├─ VisualGuidanceService 合并全局视觉 + 结构计划 ├─ AI 生成 image prompt → 图像模型 └─ 保存到 Page.generated_image_path（含版本历史）
Fast 模式成图门槛更严：通常必须有模板图、风格文字或外部 Skill；Harness 模式可用场景包默认视觉直接成图。

9. Agent 模式专属流程

AgentModePanel 提交 → 生成 DeckPlan（AI + 场景包 hint + schema 校验） → 创建 Project + Pages（大纲描述已预填） → 生成 DeckVersion / DeckVisualSystem / 全部 PageVisualPlan → Deck 级 QA（Swap Test + 连续性） → 用户编辑计划 / 锁定页面 → 风格预览（默认第 1、2 页成图） → 用户确认后批量生成剩余页 → 进入 SlidePreview 导出

Agent 的价值是先计划、再像素：用户在看到全稿图片之前，就能调整叙事顺序、单页主张和视觉计划，并用 2 页预览校验风格是否跑偏。

10. 导出阶段

格式输入方式
PPTX（图片型） 各页已生成的图片 同步导出，按页序拼成幻灯片
PDF 各页已生成的图片 同步导出
可编辑 PPTX 页面图片 + 布局分析 异步任务，尝试还原可编辑元素

导出只消费已经成图的页面；结构计划与 QA 记录保留在库里，供复盘「当时为什么这样组织这一页」。
