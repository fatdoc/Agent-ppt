/ppt-editor · 聊天驱动 PPT 文档生成架构

从聊天内容到修改文档，再到生成 PPT 大纲

这个页面是一个语义编辑器：用户每轮输入都会被后端 LLM 转换成结构化 CompetitionProjectSpec，前端再把它渲染为右侧 Markdown 稿件。确认稿件后，系统基于结构化稿件生成 PPT 大纲页面。

React + TypeScript SSE 流式交互 LLM 语义编辑 结构化 JSON 文档 Markdown 可视化稿件 Project / Page 持久化

一、核心工作流总览

用户自然语言不会直接写入页面，而是先变成结构化稿件，再渲染成文档。

1

用户聊天输入

输入项目资料、补充信息、修改意见。

2

前端组装上下文

发送本轮输入、当前 spec、可选 Markdown 手动稿和 project_id。

3

后端语义编辑

CompetitionDocumentEditService 调 LLM，生成 updated_spec。

4

结构化校验

CompetitionUnderstandingService 清洗字段、补默认值、计算缺失项。

5

项目持久化

保存 Project.competition_project_spec、idea_prompt、status。

6

前端刷新文档

applyResponse 更新 spec，再用 buildDraftMarkdown 生成右侧 Markdown。

7

确认并生成大纲

确认稿件后调用 generateOutlineStream，生成 Page.outline_content。

Markdown 稿件

# 智慧养老照护风险评估系统

## 一、项目定位
- 项目名称：智慧养老照护风险评估系统
- 赛道/专业方向：养老照护
- 真实场景：养老院护理站
- 服务对象：老人、护理员

## 二、真实问题与目标
### 痛点
- 风险识别依赖经验
- 记录归档不统一
关键点：前端不是把聊天文本直接拼到 Markdown 中，而是先更新 spec，再重新渲染 Markdown，避免聊天内容、提示词、模板标题、待补充占位污染业务文档。

七、一句话总结

/ppt-editor 是一个聊天驱动的结构化文档编辑系统。聊天只是输入方式，真正的文档状态是 CompetitionProjectSpec；Markdown 是它的可视化编辑层；PPT 大纲是基于确认后的结构化稿件生成出来的页面集合。
