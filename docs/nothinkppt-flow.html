功能关系图

入口层负责收集不同形态的用户意图；核心服务层把输入统一成页面结构；运行层把页面变成图片、可编辑 PPT 或翻新结果。

入口与输入形态

用户从首页选择一种创建方式，前端组装请求并进入对应接口。

NoThinkPPT

主题可为空或很短，搭配场景、色调、密度、页数、风格等选项，走 creation_type=no_think。

一句话生成 PPT

用户给一句主题或目标，保存为 idea_prompt，先生成大纲，再补页面描述与图片。

从大纲生成

用户输入已有大纲，保存为 outline_text，解析成页面标题和要点。

从描述生成

用户输入页面级描述，保存为 description_text，同时抽取大纲和逐页描述。

PPT 翻新 / PPT to PPT

上传 PDF、PPTX 或 PPT，必要时先转 PDF，再渲染为页面图片，异步解析并重建内容。

核心方法函数调用

主要调用点来自当前仓库的 controller、service 与 task manager。

Home.tsx 提交创建请求 createProject() 创建普通项目；NoThink 会携带 no_think_options。
NoThinkService.normalize_prompt() 把低描述输入补成包含场景、色调、密度、页数和风格模板的结构化需求。
project_controller.generate_outline() 根据 creation_type 选择 input_kind，并创建 ProjectContext。
InputGenerationService.generate() 统一执行 build_outline()、build_descriptions()、save_pages()。
AIService 文本方法分流 generate_outline、parse_outline_text、parse_description_to_outline、generate_page_description。
create_ppt_renovation_project() 上传文件、PPT 转 PDF、PDF 渲染页面图、创建 PPT_RENOVATION 异步任务。
process_ppt_renovation_task() 解析每页原始内容，生成或回填 outline 与 description，DetailEditor 轮询任务进度。
VisualGuidanceService.build_visual_guidance() 把模板优先级、页面内容、布局备注和覆盖规则整理成视觉提示块。
generate_images_task() / AIService.generate_image() 逐页生成图片，保存图片版本，并把页面推进到可预览、可导出状态。
ExportService 输出 PPT create_pptx_from_images() 输出图片型 PPT；create_editable_pptx_with_recursive_analysis() 输出可编辑 PPTX。

运行状态与数据产物

每个阶段都会改变项目状态或页面内容，供后续编辑器、预览和导出使用。

DRAFT

项目刚创建，原始输入已保存，页面可能还没有生成或只有占位数据。

OUTLINE_GENERATED

页面已有 outline_content，用户可进入大纲编辑器检查结构。

DESCRIPTIONS_GENERATED

页面已有 description_content，可直接进入详情编辑与图像生成。

PROCESSING

PPT 翻新异步解析中，前端通过任务进度展示 completed / total。

导出文件

最终产物包括图片型 .pptx、可编辑 .pptx、PDF、图片包或视频。

程序运行链路

从输入到 PPT 输出可以理解为六段流水线；不同入口只是在前两段使用不同的解析策略。

1. 创建项目

前端提交 creation_type 与原始输入，后端创建 Project。

2. 归一化输入

NoThink 补全 prompt；大纲和描述入口保留用户结构，减少二次解释。

3. 生成文本骨架

InputGenerationService 产出 outline，按需要生成 page descriptions。

4. 写入页面

save_pages() merge 或 replace 页面，更新项目状态。

5. 生成视觉

视觉指导层生成 prompt，图片模型逐页生成并保存版本。

6. 输出 PPT

预览确认后，导出图片型 PPTX 或递归分析生成可编辑 PPTX。
