Banana Slides / Outline To PPT

从大纲到 PPT 的生成链路

这条链路把“已有结构”转成可交付演示稿：先保留用户的大纲意图，再补齐页面描述、视觉提示、图片渲染和导出文件。核心目标是让 AI 不重新猜主题，而是沿着用户给出的结构稳定生产。

查看链路 方法调用 结果产出
输入

用户粘贴标题、章节、要点，创建 creation_type=outline 项目。

解析

优先本地解析大纲；复杂格式再交给 AI 解析为结构化页面。

生成

逐页生成描述，再调用图像模型渲染每一页幻灯片画面。

交付

输出图片型 PPTX、可编辑 PPTX、PDF、图片包等下载结果。

步进表单与主链路

左侧模拟用户侧的三步表单，右侧对应后端实际生产链路。大纲入口的关键是“结构先行”，后面的描述、图片和导出都围绕结构展开。

生成配置
比例 默认 16:9，也可根据项目改成 4:3、21:9、1:1 或 9:16。
风格 模板图、文本风格或自定义样式作为视觉参考。
语言 传入 zh、en、ja 或自动识别。
材料 参考文件解析后进入上下文，辅助描述生成。
提交动作
POST /api/projects 创建项目并保存 outline_text。
POST /generate/outline 解析结构化页面，进入大纲编辑器。
Input

创建项目，锁定入口类型

前端提交 creation_type: "outline"、outline_text、比例、模板风格。后端创建 Project，初始状态为 DRAFT。

Outline

大纲解析为页面结构

InputGenerationService.build_outline() 对 outline 入口先尝试本地解析；无法稳定拆分时调用 AIService.parse_outline_text()，得到页面标题、要点和章节。

Page

保存页面草稿并支持编辑

save_pages() 按页面顺序写入 Page.outline_content。用户可在大纲编辑器里增删、拖拽、改标题和要点。

Description

逐页补全画面描述

确认大纲后调用 POST /generate/descriptions。任务层并发调用 AIService.generate_page_description()，把内容结构转成可渲染的页面描述。

Render

基于描述生成幻灯片图片

POST /generate/images 创建异步任务，组合页面描述、模板风格、比例和视觉约束，调用图像模型生成每页成图。

Export

导出可交付文件

ExportService 将生成图片写入 PPTX/PDF；可编辑导出会进一步做版面元素提取和背景修复，生成可编辑 PPTX。

思路拆解

这条链路不是“一步到位生成 PPT”，而是分层生产：结构层、表达层、视觉层、交付层各自负责一个稳定目标。

先结构，后创作

大纲入口意味着用户已经给出叙事顺序。系统只把它标准化，不主动改写核心逻辑，避免跑题。

每页独立扩写

大纲拆成页面后逐页生成描述，既能并发提速，也便于单页重试、编辑和状态追踪。

图像与导出解耦

图片生成完成后才进入导出层，同一批页面可复用到 PPTX、PDF、图片包和可编辑 PPTX。

鱼骨图：影响结果质量的关键因素

鱼头是最终 PPT 质量，鱼骨展示从输入到导出的主要影响项，方便做评审或对外介绍。

结果产出

面向用户展示的是 PPT 文件，系统内部同时保留多个中间层，方便继续编辑、重试和多格式导出。

结构化大纲

每页包含标题、要点和章节信息，是后续描述、图片和导出的共同索引。

页面描述

把内容转成画面说明，包含布局、视觉风格、图表表达和文本约束。

幻灯片图片

每页生成一张可预览、可重试、可版本化的图片，作为导出的基础素材。

交付文件

输出图片型 PPTX、PDF、图片包；需要二次编辑时可导出可编辑 PPTX。

一句话总结：从大纲生成 PPT 的本质是“用户给结构，系统补表达，模型出画面，导出层交付文件”。这样既保留人工构思，又利用 AI 完成高成本的页面设计与批量生产。
