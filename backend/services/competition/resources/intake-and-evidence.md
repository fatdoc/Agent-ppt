# 输入整理与未知信息处理

## 一份材料即可开始

接受混乱逐字稿、项目方案、旧 PPT/PDF、口述、笔记、代码与系统截图。按可用工具读取；扫描件需要识别画面时查看原页，不将 OCR 猜测作为确定技术名称。无需所有种类齐全。材料不可读时说明具体问题，只请求必要的可读替代，不要求重写整份方案。

整理维度是智能体内部工作，不是用户必填表：

| 维度 | 提取内容 |
|---|---|
| 定位与需求 | 项目名、服务对象、场景、核心问题、总任务 |
| 方案 | 模块、技术、设备、数据来源、业务闭环、当前实现范围 |
| 岗位 | 实际成员、职责、上游输入、关键操作、输出与接收方 |
| 现场 | 前期已完成内容、现场实际操作、运行效果、交接与异常处置 |
| 成果 | 实物/软件、测试、交付、合作、知识产权、应用反馈 |
| 展示条件 | 比赛与评分文件、时长、视觉参考、设备/网络等已知限制 |

保留文件名及页/段/代码位置。材料声称“已经完成”只能先记作“材料陈述”；代码存在不等于部署或实测通过。经查看符合声称的日志/报告等才升级为“证据支持”，需有实际运行观察才可称“本次验证”。

## 问法与停止追问条件

- 先说明已经理解的项目任务，再集中问影响范围、岗位、现场操作、时长及冲突的问题；一次通常不超过3个问题，可以把相邻小项合成一个问题。
- 采用“材料缺少什么→为什么影响页面→建议怎么填→允许修改或不知道”的问法。
- 示例问法（是交互范式，不是项目默认事实）：材料尚未说明谁接收上一岗位的输出。依据当前任务，我建议由负责集成的岗位接收并核对结果；你可以采用、调整，或让我按此方案继续。
- 每个缺口记录已问/用户补充/用户未知/已代拟/待证据，避免换词重问。
- 用户明确不知道后立即切换处理方式。对关键事实冲突无法确认，缩小到两说都支持的内容；必须保留的分歧写入清单，不擅自判定已完成版本。
- 用户要求先生成或全部由智能体安排时，使用有说明的建议方案继续。没有用户答复不视为确认事实。

## 按信息性质补充

| 缺失类型 | 可以主动做的事 | 不可跨越的边界 |
|---|---|---|
| 标题、结构、文案 | 精炼、重排、归纳 | 不借改写新增已实现能力 |
| 岗位、现场步骤、交接 | 基于任务拟定建议分工/流程 | 不写成用户已经执行的历史事实 |
| 技术名称或参数 | 查材料、代码、配置；给选择理由、推荐范围或方案 | 不将推荐配置说成当前运行配置 |
| 公开政策、标准、行业数据 | 查官方来源，核日期、口径、版本和适用性 | 不靠标题相似断言适用；不可生成不存在的标准号 |
| 性能、时延、准确率 | 查已有报告；拟定测试输入、环境、采样方法和输出记录 | 不虚构成功率；目标值与实测值不能混用 |
| 成本及收益 | 查账目、物料记录；基于明确假设进行测算 | 测算标明单价来源、数量、范围；不宣称实际收益 |
| 合作、获奖、权属、落地 | 查对应证明，标清申请/受理/授权等状态 | 不代拟机构名、奖项、证书或已落地规模 |
| 素材 | 指定应补画面、可见内容和对应页面 | 不生成真实合影、截图、日志、代码、证书充证据 |

需要推荐现实技术、参数或公开政策时，使用当前可靠来源；涉及标准版本、法规或其他高准确性内容时进一步核实。工具不可用或来源无法确认时，保留待核实状态，以有边界的文案完成页面。模板制作阶段只写字段和素材要求，不预填具体政策/标准。

## 状态与记录

内部及清单使用以下含义，页面需要时可用自然语言短标记：

- 材料陈述：输入材料中存在，尚未独立核验。
- 证据支持：有与结论匹配的记录、图片、代码或报告，写明支持范围。
- 本次验证：本次实际检查或运行观察到了相应结果，不超出检查范围。
- 建议方案：智能体代拟，尚未确认实际采用或实现。
- 推荐参数/目标值/测算值：分别注明用途、依据或假设，不能归入实测结果。
- 待核实/缺失：尚未确认或没有材料；在清单给出补充/替代办法。

“规划中”描述完成状态，“建议方案”描述方案来源，两者可以同时成立。参数的性质保留在页面相关数值附近，不能只藏在清单里。

## 清单如何帮助用户

按三组呈现：已提取事实及依据、智能体代拟与建议、待确认及素材需求。每项写对应页码、内容/状态、来源或理由、用户下一步或替代处理。没有待补也明确写“当前未列出额外待补项”，不要捏造任务。

用户不知道实测参数时，清单中应出现可执行的测试方法或替代表达，而不是再次写“请填写准确率”。缺素材时说明画面主体和必须可见内容，而不只写“补截图”。

## 有逐字稿时的内容分配

先标出逐字稿已解释、现场已安排、尚未覆盖的内容，补问和补写只针对缺口。技术选择原因、规范适用说明、操作时间、成本测算口径通常由逐字稿承担；PPT用相应画面和短标签承接。完整异常协作放核心技能最后的全场景演绎环节，明确发现、报告、接手、恢复、共同复核并回归业务主线。提示写入统一记录的 speaker_notes/action_notes，生成到配套清单，不写成PPT正文。
