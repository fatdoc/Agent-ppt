# 输出、同步与呈现契约

## 默认页面与可调整范围

页面内容唯一来源为 [page-blueprint.json](page-blueprint.json)。五章固定名称：项目设计、工作流程、核心技能、成果展示、未来展望。默认47页、四岗各五页；页数不是官方要求。新增/合并内容页不改变章节顺序，按实际总页数连续重排。

五个过渡页保留。各岗位的方案、难点、创新、操作、验证五种用途应保留；经用户确认的压缩可合页表达，不能为了减页丢掉操作或结果验证。每次改页序，要重新生成清单页码映射。

不要默认所有项目都有机器人、视觉识别或特定模型。实际岗位名来自工作内容；四岗是模板默认编排，不是官方参赛人数结论。团队人数与默认不同则说明影响并按用户实际情况调整。

## 默认关键页序

第1页封面，第2页四人团队介绍（四列成员照片、岗位与职责），第3页目录；团队介绍归属开场，不显示章节导航。

第16页为核心技能总览，第17页为技术规范与开发依据；第18—22、23—27、28—32、33—37页分别为四岗五页；第38页全场景演绎；过渡页为第4、10、15、39、46页。异常协作放全场景演绎中，不再分散到第14页或每岗验证页。

## 应用价值的分配与去重

| 内容 | 融入位置 | 呈现要求 |
|---|---|---|
| 实用性与需求价值 | 项目设计的需求、痛点、整体方案 | 说明服务对象、实际场景、问题和预期改善；预期目标不写成已实现成效。 |
| 实用性与业务适配 | 工作流程的业务闭环、岗位交接 | 通过减少重复操作、明确交接与反馈体现，不增加口号页。 |
| 降本、节能、节材的实现方法 | 核心技能中确实相关岗位的方案、创新、验证 | 结合真实技术与操作说明，不强制每岗重复价值条目；操作页仍以操作画面为主。 |
| 经济性与绿色可持续成效 | 成果展示的创新成效页 | 同口径呈现成本、工时、效率、用水、用电或耗材等适用指标；选择最相关的两三项，测算与实测区分。 |
| 社会价值 | 成果展示的项目落地与应用反馈页 | 用实际受益对象、场景、反馈和改进证明作用。 |
| 教育价值 | 成果展示的职业素养与育人成果页 | 展示岗位能力、教学资源转化和实训应用依据。 |
| 推广潜力与长期价值 | 未来展望的应用拓展路线 | 写清场景、条件、阶段验证与后续计划，不写成已有覆盖或实际收益。 |

默认删除旧骨架的应用价值过渡页和汇总页，49页变为47页；前45页的页序保持，未来展望为第46—47页。若有足够材料且现有页过密，可新增“成本与资源效益”页并同步重排，不强行维持47页。

同一价值按“目标—方法—证据—计划”前后呼应，不重复整段表述。成本范围、比较基准、测算假设放讲稿提示，页面保留必要单位、状态、口径与来源。绿色价值应有真实资源节约或环保实践，不能仅用可升级、可维护替代。缺结果时写验证安排，不编造收益比例。

迁移已有六章稿件时，先读取原稿与统一记录，按上表保留并分配原应用价值内容，再删除独立章节、将主要成果统一为成果展示、未来展望改为第五章，重建页码和清单映射；不能直接删页丢内容或用默认骨架覆盖用户改动。

## 两份主文件

两份主文件直接从 `第 1 页：标题` 开始，不添加总标题、前言、开头描述或全局制作说明。通用规则保留在 Skill 中，需要交付的全局提醒放配套清单；逐页栏目照常保留。正文每页以 `第 X 页：标题` 开始，两份标题逐字一致。正文页头不要加 Markdown 标题前缀。该页头是切分标记，不是幻灯片可见文字。

大纲每页包含：页面类型、所属章节、展示用途、核心内容、主画面建议、素材要求、导航要求。

逐页描述每页包含：页面类型、所属章节、页面文字、页面画面与版式、展示用途、素材要求、导航状态。

“页面文字/核心内容”放拟展示内容；其余是制作说明，不要将“素材要求”“待确认清单”“导航状态”等字样直接画进 PPT。事实状态不能因精简而被抹去。没有依据的结果改成测试安排/待验证内容，不统一标已通过。

正文使用简短状态词，例如“建议流程”“待验证”“申请中”。“本轮材料没有提供”“不要生成伪证据”等制作解释放在素材要求或配套清单，不让评委页面变成资料检查报告。四岗结果验证分别核对本岗产出，不把同一段通用测试说明重复四次。

## 内容密度

一页优先承载一个主题，用主图和少量短标注表达；通常两三处短标注即可。目录、四岗矩阵、流程、代码与表格不机械限制为三条，但要保证主次清楚。若必须缩小正文才能塞下，先移除重复解释、转入讲稿，再判断拆页；不要把所有评分补充项转成可见清单。

第17页只选2—3项适用规范/开发材料，名称加一句执行要点，适用性由讲稿解释。第38页一条主业务线，在异常节点加简短处理与恢复状态，避免正常/异常两套完整图同时上屏。预设异常演练如实说明。

## 版式与导航

- 16:9。默认标题32—36pt，正文18—22pt，来源14—16pt，导航12—14pt。优先精炼内容而非缩小文字。视觉参考决定字体、配色与装饰；无参考时使用统一、克制的版式，不引入项目外的功能图标。
- 首页左标题右场景；团队页四列照片/岗位/工作；痛点页默认三列图文。架构按实际层级组织，不能强塞固定技术层。
- 内容页右上角完整五章导航，当前章主题色加深背景并加粗，其他章常规状态，导航与标题分区避免挤压。首页、开场团队介绍、目录、过渡页完全无导航。所有画面无页码/页数分式。
- 五张过渡页统一为章节编号、标题、关键词，不放长正文、截图、表格或导航。
- 四岗展示页（默认第18—37页）统一保留左侧岗位流程栏，占宽约18%—22%：顶部为本岗工程师/岗位名称，下方通常4个实际工作环节，以纵向节点和箭头连接。流程名称来自本岗真实工作，同岗各页名称、顺序与位置一致；未知时可代拟建议并记清单。4个流程不等于4页，也不是“方案简介、技术难点、创新点、技能操作、结果验证”这些页面用途。
- 当前涉及的流程节点深色底、对比色文字，其余浅色；跨环节页可高亮相关节点，总览页可全部常规显示。每页根据实际内容选择对应环节，不硬套固定映射。
- 右侧内容区上方为本页标题，下方呈现当前技能内容：简介页以效果和少量标签为主；操作页展示关键代码/配置、运行画面及必要日志；结果页以实际运行效果为主。岗位主流程不在底部重复绘制，当前环节的必要子步骤可在内容区简短说明。参考图只提取岗位流程侧栏结构，不照搬示例项目的岗位名称、技术、配色、章节顺序或页码。
- 操作页注明“操作时停留，不单独安排整页讲解”；验证页注明“同步展示运行效果”；这些是制作/演示安排，不是默认生成逐字稿。
- 政策页预留习近平相关公开活动真实画面，选取与政策主题相关的官方素材，标清来源及场景；缺素材可用占位，不合成活动新闻画面、不暗示项目背书。
- 通用模板只有【通用字段】；具体项目稿替换为资料或有说明的建议，不让占位词堆满页面。照片、日志、代码、证书不能伪造，示意画面注明示意。

## 内部 JSON：由智能体填写，不交给用户填表

`render` 接受一个 UTF-8 JSON 对象：

| 字段 | 含义 |
|---|---|
| `project` | 项目名，用于文件名，未知可代拟并在清单记录 |
| `mode` | `project` 或 `template` |
| `pages` | 按最终顺序的页面对象列表，数组位置即最终页码 |
| `checklist` | 三类清单项数组，见下表 |

页面对象：`title`（完整页头标题）、`kind`（`cover`/`contents`/`transition`/`content`）、`chapter`（1—5；首页、开场团队介绍和目录为0）、`purpose`（展示用途）、`text`（页面文字数组）、`layout`（版式说明数组）、`materials`（素材要求数组）。每项均必填且非空；无额外素材可明确写“无独立素材，按页面文字排版”。导航由脚本依据类型和章节计算，不由模型逐页手填。数组位置负责页码，不另存会过期的编号。

页面可选 `speaker_notes` 与 `action_notes`，均为单行字符串数组，可为空。分别存讲稿对照/补充和现场动作/同步提示；只进入配套清单的“讲稿与现场提示（不上屏）”，不进入大纲或逐页描述。旧项目记录缺这两个字段仍可生成，不自动增加页面。

新建稿件将技术选择理由、详细测试口径、时间分配、安全伦理说明放入这些提示；优先对照现有逐字稿，仅补缺口。屏幕仍保留必要的结果状态、数据口径和来源短标记。不能因为移入讲稿而把未验证说成已验证。

清单项：`category` 为 `fact`/`proposal`/`missing`；`pages` 是最终页码整数数组；`content`、`status`、`basis`、`action` 为非空字符串。`basis` 写来源位置、推荐理由或“暂无依据”；`action` 写补充办法或“无需额外操作”。清单页码必须在1到实际总页数范围内。全局事项可关联全部相关页，不使用过期页码。

推荐从骨架复制到 `<输出目录>/.ppt-input/<项目名>.json`，再用材料逐页改写。骨架结构是内容字段，不是将材料自动套进占位词的算法。大纲和描述共享短文案；描述的详细画面安排放 `layout`，避免长段落塞入可见正文。

对已有 Markdown 的修改，先将用户有效内容和样式说明还原到统一记录，再局部改动。不要直接用骨架覆盖，也不要在用户改过 Markdown 后只信旧 JSON。

```bash
python3 backend/services/competition/skill_contract.py render <页面记录.json> --output-dir <输出目录>
python3 backend/services/competition/skill_contract.py validate <大纲.md> <描述.md> --checklist <清单.md>
```

文件覆盖自动保留在输出目录 `.ppt-input/backups/<时间戳>/`。保持内部记录和三份输出同源；最终给用户三份 Markdown 链接即可。

## 校验与边界

脚本检查数据结构、五章顺序与过渡、双文件页数与标题、连续编号、页面类型/归属/导航、描述字段和清单页码。允许实际页数变化；不接受导航出现在免导航页，也不接受错误章节高亮。模板专用导出使用47页默认骨架，并生成 `2026世界职业院校技能大赛通用PPT待确认与素材清单.md`，保留讲稿和现场提示。

人工检查：没有借模板增加功能；不同岗位内容真实区分；重复的创新/流程各有用途；推荐参数未写为实测；缺证有替代方案；政策/标准来源可靠；素材要求可执行。结构通过不等于事实成立，不代表实际 PPT 已制作或经过视觉验收。
